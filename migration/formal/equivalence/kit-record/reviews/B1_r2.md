## Findings

### 1. PRECOND — `def:flag`: a non-Boolean `cond` gives Float64 where Python gives Int64 or raises

Source `sas_compat.py:124` (`cond.fill_null(False).cast(pl.Int64)`). On
`fz = {i: Int64 [null, 0, 1, 5, -2], x: Float64 [null, 0.0, 1.0, 2.5, NaN], b: Boolean}`:

| Call | Python | Lean |
|---|---|---|
| `fz.select(flag(pl.lit(None)))` | Int64 `[0]` | a Float64 column of 1 value |
| `fz.select(flag(pl.col("i")))` | Int64 `[0, 0, 1, 5, -2]` | a Float64 column of 5 values |
| `fz.select(flag(pl.col("x")))` | raises `InvalidOperationError` (NaN to i64) | a Float64 column, no precondition |
| `fz.select(flag(pl.col("b")))` | Int64 `[0, 1, 0, 1, 0]` | the same (PASS) |

Cause: the prelude's `Col.fillNull` sends any pair of different kinds (`.int`/`.bool`,
`.null`/`.bool`) to the Float64 branch, and `Expr.castI64` passes a non-Boolean column through.
RULEBOOK §2.3 lists `e.cast(pl.Int64)` for "Boolean/int input", so the Int64 row is inside the
rule's stated domain.

`flag` has no precondition item and its comment does not say the argument must be Boolean, so by
the letter of the reviewer brief this is a difference on an allowed input. No call site reaches
it: all 36 `flag(...)` calls in `credit_risk/` pass a comparison, `is_null()`, or a
`lt`/`ge` result. Either state "`cond` evaluates to a Boolean column" where `flag` is specified,
or have the prelude's `fillNull` keep the column's dtype. The prelude is not mine to edit; evidence
is above.

### 2. NOTE — `def:_has_bare_column` departs from the §4 statement shape

It is `def _has_bare_column : Pl.Json → Bool` with no `{α : Type} [Tabular.RealLike α]` and with
`where` helpers (`dictAny`, `pairVal`, `listAny`). The item's comment gives the reason (no number
type occurs; structural recursion over the nested type). An unused implicit `α` could not be
inferred at the call in `_is_scalar`, so I see no better form. Recorded as a deviation from the
letter of §4, not a request to change it.

### 3. NOTE — known `ser` gaps do not reach the call sites

The two places where the prelude's serialization skeleton is already known to differ from polars
(`pl.col("x", "y")` serializes as a selector; `map_batches` cannot be serialized, so
`_is_scalar(div(…))` raises in Python) are not reached: no `div` operand in the package is a
multi-column selector or another `div`. All 17 real operands and all 10 pairs agree.
