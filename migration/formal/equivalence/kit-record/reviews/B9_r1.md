## Findings

### 1. PRECOND — shape mismatch of a step's `beta` / `cov` (train.py:192-193)

`def:train_run_03_fit_global_rsquare_precond` requires, for every step,
`∃ b, st.fit.beta = Np.NDArray.d1 b` and `∃ c, st.fit.cov = Np.NDArray.d2 c`, nothing about their
sizes. The unit's trailer and the header of the precondition put only "LinAlgError … on a singular
matrix" outside the model. But `np.linalg.solve` also raises when the shapes do not fit, which is
not singularity:

| `st.fit.beta` | `st.fit.cov` | Python at :193 | Lean |
|---|---|---|---|
| `[0.2, -1.5, 0.75]` | 2×2 `[[0.5, 0.1], [0.1, 0.3]]` | `ValueError: solve1: Input operand 1 has a mismatch in its core dimension 0 … (size 2 is different from 1)` | `dot b_slope (solve cov_slope b_slope)`: a value |
| `[0.2, -1.5]` | 3×3 | the same `ValueError` | a value |
| `[0.2, -1.5, 0.75]` | 2×3 | `LinAlgError: Last 2 dimensions of the array must be square` | a value |

(Python results obtained by running the expression of :193 on these arrays.) Such a step satisfies
the accepted precondition, and nothing else in `def:run_py_py_py_precond` constrains the fits of
`stepwise.steps` (steps 04 and 06 constrain `final` only). Needed: `cov` is square with as many rows
as `beta` has entries (which also excludes the ragged `d2` lists that no ndarray can be).
The other `@` / `solve` site of the loop (:189-191) is safe: `i0` and `u0` have matching shapes by
construction.

### 2. RULE §4 — narrowings without a `-- narrowing:` comment

§4: "Every input that is excluded although Python does not raise carries a comment saying so."

- Step 03 precondition: `isFinite (exp ((-(m2ll0 - …)) / n_obs)) = true` and
  `isFinite (exp ((-m2ll0) / n_obs)) = true`, commented "raises OverflowError". `math.exp` raises
  only on a finite argument that overflows: `math.exp(float("nan"))` is `nan` and
  `math.exp(float("inf"))` is `inf` (run). A step with `loglik = NaN` is excluded although the run
  does not raise there.
- Step 06 precondition: the three `isFinite (exp …) = true` conjuncts, same remark (`b = NaN`).
  The `pow2` conjunct is written correctly as an implication.
- Step 03 and step 08 preconditions: every column named by a fit after the intercept is Float64
  "with no null (complete cases)". A fit may name a column that is not a candidate; a null there
  becomes NaN in `x_k` / `x_final` and `np.linalg.solve` returns NaN without raising (run). The
  comment explains why the condition is expected, not that it is a narrowing.
- Step 04 precondition: `b.length = final.names.length`. `final.beta[i]` raises only when `i` is out
  of range; a `beta` longer than `names` does not raise.

None of these lets a wrong value through; they make the stated domain smaller than the one on
which the Python runs.

### 3. RULE §2.3 — `getF` on Int64 columns

§2.3 gives `df.getF "x"` for a Float64 column and `getI` for Int64. `def:train_run_07_hl` reads
`Total` (Int64 in `def:hosmer_lemeshow`) and `def:train_run_08_ctable` reads `CorrectEvents`,
`IncorrectEvents` (Int64) through `getF`, relying on what the prelude's `getF` does with an integer
column. The comment in both units says so ("an integer is cast"). The values agree with Python in
the implementer's run and in my test T2 (`printed_hl_partition.csv.Total`), so this is a deviation
from the table, not a difference. The columns that are Float64 only because of R-F2I carry the
`TODO(port): F2I`, as required.

### 4. RULE §4 — frame wording missing in four preconditions

§4 fixes the wording for a frame: distinct column names, every column of the frame's height, each
column read present. The preconditions of steps 05, 07 and 13 state only the presence of the two
columns and delegate; step 15 states presence, kind and length but not distinct names. Inside
`run` the frames come from earlier steps and are well formed, so the composed precondition is not
affected.
