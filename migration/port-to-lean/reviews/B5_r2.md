## Verdict

No DEFECT, no RULE, no PRECOND finding. 15 cases, 118 compared values, 117 equal bit for bit.
The one difference is not in a unit's result: it is one element of the intermediate `ps` of

## Method

Inputs were produced by fitting, as `train.py` does (train.py:78-90, 238-256, 378-386):
`feature_engineering.run(data, tmp, split_ids=inputs/split_ids.csv)`, the file
`model_features_train.csv` read back with `proc_import_csv(path, guessingrows=None)` (all columns
Float64, 105000 rows), seeded row samples, complete cases, `x = np.column_stack([np.ones(n), cols])`,
`fit = sas_compat.fit_logistic(x, y, names)`, and `pd` by the polars expression of train.py:244-252
(`1 / (1 + (-eta).exp())`, `eta = lit(b0) + b1 * col + …`). Then
`hosmer_lemeshow(Series y, Series pd)` and `classification_table(y, x, pd=pd)` in Python, and the
same calls in Lean through `eval_decl(def:zz_carrier)` at `α := Float`.

Compared per case (each a 64-bit digest over the exact tokens; floats by their bits):
the inputs as Lean decoded them (y, pd, x: guards the transcription); `hosmer_lemeshow`: the whole
table (6 columns, every row), chisq, dof, p; `classification_table`: the whole frame (12 columns,
every row, nulls included); and three intermediates through `classification_table_adj` and
`_expit`: `eta` (sc:1073), the argument of the last `_expit` (sc:1083), and `ps`.
R-F2I columns (EventsObserved, NoneventsObserved; CorrectNonevents, IncorrectNonevents) were cast
to Float64 on the Python side: values compared, not dtypes.

Library parameters: `chi2` and `pow2` are tables keyed on the argument bits (and df) returning what
scipy / Python `x ** 2` returned, a sentinel (-7.25) otherwise; `log1p` a table keyed on the bits of
`-pd_i` returning `np.log1p`; `inv`, `matmul`, `einsum_q` return numpy's result only if the digest of
the arguments Lean passes equals the digest of the arguments numpy received (so `x.T`, `x * w[:, None]`
and `v` are checked bit for bit too), an empty array otherwise; `matvec` returns `[]` (the `pd=`
path never calls it).

## Findings

**N1 (NOTE) — `Float.exp` on the evaluation server is not numpy's `exp` on this machine; seen in
`ps` (sc:1083), not in any unit result.**
Case s1: the 200 arguments of the last `_expit` are equal bit for bit in Lean and Python, the 200
values of `ps` are not: element 164. Drill-down on the 200 arguments (`Float.exp (-a)` against
`np.exp(-a)`, which equals `math.exp(-a)` on all 200):

| i | a (bits) | Lean `exp(-a)` bits | numpy `exp(-a)` bits | Lean `1/(1+e)` bits | numpy bits |
|---|---|---|---|---|---|
| 82 | 13835113922771374117 (-2.0248101491397557) | 4620214341770956299 | 4620214341770956300 | 4593067959333264841 | 4593067959333264841 |
| 164 | 13838379705478786569 (-3.4751090112165497) | 4629742828116231353 | 4629742828116231354 | 4584312437488584229 | 4584312437488584227 |

Against a 60-digit reference the Lean value is the correctly rounded one both times (error 0.49995
and 0.49889 ulp; numpy 0.50005 and 0.50111 ulp). So 2 of 200 realistic arguments differ by one ulp
in `exp`, one of them moves `ps` by 2 ulps. The classification table of s1 is equal, because no
`ps` is within 2 ulps of a grid value there. It is not a translation difference: the Lean applies
`RealLike.exp` where the code applies `np.exp` (RULEBOOK §2.2), and the four IEEE operations around
it agree. Consequence for the harness and for any later Float-level comparison: a
`classification_table` (or `_expit`) case can differ from Python only because of the host's `exp`
when a `ps` lies within a few ulps of `k * 0.02`; p3 (ps exactly 0.8) happened to be equal. In the
other 9 CT cases (2577 `_expit` evaluations, a few hundred distinct arguments) `ps` was equal on
every element. `eta` (through `RealLike.log` against `np.log`, `log1p` being a table) was equal on every
element of every case.

**N2 (NOTE) — what was not evaluated.** Two generated cases were not run for cost (every input has
to be typed into the `eval_decl` call): a 797-row sample with 728 distinct pd (HL only; 10 groups of
80, 80, …, 77) and a 23-row one-class sample. Group sums over more than 128 values are covered by s2
only with tied values (19 distinct pd), sums of 20 to 30 distinct values by s1, s3b, p3, p4. The
`fit=` path of `classification_table` (`matvec`, `_expit` on `x @ beta`) is not used by the package
and was not exercised here; null / Int64 / Boolean input Series of `hosmer_lemeshow` neither (train.py
passes two Float64 columns without nulls after the complete-case filter).
