## Findings

### 1. DEFECT — classification_table: unbounded `n1` (sc:1087-1088, 1104-1118; R-F2I)

Python keeps `n1 = int(y.sum())`, `n0 = len(y) - n1`, `cn`, `inn`, `ce + cn`, `n1 + n0`,
`cn + inn` as exact ints. The Lean does this arithmetic in α. Clause (8) of the precondition only
asks that `Np.sum y` is finite and integral.

Input: `y = [2^54, 1.0, 0.0]`, `x = [[1.0],[1.0],[1.0]]`, `pd = [0.3, 0.5, 0.7]` (keyword form).
The precondition holds: ranks and lengths, `0 < pd < 1`, `h_i = w_i / Σw < 1`, `ps` has no NaN,
`klo = 0`, `khi ≤ 50`, `y.sum() = 2^54` finite and integral. Python runs and returns 47 rows.
The library routines were passed as the digest-keyed lambdas of `b5_gen.py`.

Cause: Python `n1 + n0 = 3`; in Float `n0 = 3 - 2^54` rounds to `-(2^54 - 4)`, so `n1 + n0 = 4`.
Fix belongs in the precondition (for instance `|n1| ≤ 2^52`, as `_hl_groups_precond` does for its
integers), with the narrowing comment.

### 4. PRECOND (minor) — hosmer_lemeshow: no exactness bound on `o1` (sc:1017, 1020)

Input: `y = [9007199254740994.0]` (2^53 + 2), `pd = [0.3]`. Python row:
`(1, 1, 9007199254740994, 0.3, -9007199254740993, 0.7)`. Lean NoneventsObserved is
`-9007199254740992.0` (bits 14069245235905429504): `1 - (2^53 + 2)` is not a double. The two
agree only after the harness casts the Python Int64 column to Float64 (round to even); chisq is
bit-identical because Python's `float(o0)` rounds the same way. RULEBOOK §6 records "integers
beyond 2^53" as a limit, and `_hl_groups_precond` states its bound, but
`hosmer_lemeshow_precond` states none for `o1`. One bound (`|o1| ≤ 2^52` per group) settles
findings 3 and 4.

### 5. RULE §4 — exclusions on which Python runs, without a narrowing comment

§4: "Every input that is excluded although Python does not raise carries a comment saying so
(`-- narrowing: …`)".

- `hosmer_lemeshow_precond` excludes a String `y` / `pd`. Its comment says only that polars
  "raises on a non-number". `hosmer_lemeshow(pl.Series(["1","0"]), pl.Series([0.3,0.4]))` runs
  and returns `[(1, 1, 1, 0.3, 0, 0.7), (2, 1, 0, 0.4, 1, 0.6)]`.
- `classification_table_precond` requires `pv.length = yv.length`. numpy broadcasts a length-1
  `pd`: `classification_table(y3, ones((3,1)), pd=np.array([0.3]))` runs and returns 22 rows. The
  comment does not say so.
- Clause (6) (`1.0 - h_i ≠ 0`) says "no exception" but not that the input is excluded although
  Python runs: `classification_table(np.array([1.0]), np.ones((1,1)), pd=np.array([0.3]))`
  returns a 1-row table.
- None of the four preconditions uses the `-- narrowing:` form; the exclusions they do
  acknowledge (`0 < pd < 1`, non-integral sums, the overflow of the squares, huge integers in
  `_hl_groups`) are in prose in the header.

### 6. NOTE — hosmer_lemeshow: dtype depends on emptiness

The empty table (sc:988-998) has `EventsObserved` and `NoneventsObserved` as `Pl.Col.int []`
(the Python dtypes); the non-empty table has them as `.f64` (R-F2I, stated in the comment and in
the trailer). In Python both are Int64. The statement says each half but not the inconsistency; a
consumer that matches on the column kind sees two kinds.
