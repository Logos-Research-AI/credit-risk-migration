## Method

1. **Inputs are built inside Lean from a seed, never typed.** Use `kit.GEN` (`gF`, `gI`, `hsh`) and
   its Python mirror `kit.gF`, `kit.gI`, `kit.hsh` (`diffeval/kit.py`), through `suite.Suite` with
   `gen=True` (`digest_body` or `ints`: the Lean body enumerates the seeds itself, e.g.
   `(SEEDS.map (fun s => dg (tR (unit (mk s)))))`, so one eval call carries hundreds of cases).
   `diffeval/units/t1_gen.py` (group RG) is a worked example. The carrier of your stage is
   `def:zz_carrier_s/_f/_p/_m/_t` as before.
2. **Pools that hit the edges of the unit.** Draw from an edge list with a high share (`pe` 40-70):
   null, NaN, +inf, -inf, +0.0, -0.0; each threshold of the unit exactly and one ulp either side;
   very large and very small magnitudes (1e300, 1e-300, subnormals); integers stored as floats;
   ties and duplicates in keys and in sorted columns; empty and one-row frames; groups with no
   member; all-null columns. For String columns: "", ".", "NA", numbers with spaces and signs
   (build strings by index into a pool with `gI`). Vary the number of rows with the seed (0, 1, 2,
   a few, a few dozen).
3. **Expected values**: the port's own code on the same generated values: the real function for a
   `sas_compat` unit; for a step, the source lines executed as in the unit's existing generator
   (`diffeval/units/t*_gen.py`); for a composition, the real `run` on generated small files. Explicit
   parameters (`input_best32`, `sas_best12`, `sas_best`, ...) stay lookup tables made from the real
   functions over the values the generated inputs can hold.
4. **Precondition**: evaluate the unit's precondition in Python on every generated input (write it as
   a Python function from the text of `def:<unit>_precond`; say in the generator's docstring how each
   clause was rendered). Then, per generated input:
   - precondition admits, Python returns: a **kept** case. Lean must equal Python.
   - precondition admits, Python raises: a **defect** of the precondition. Not sent to Lean; record
     the seed in `python_raises_inside_precondition`.
   - precondition rejects, Python returns: sent to Lean too, marked `"fz": "rejected"`. Where Lean
     equals Python it is counted as a **narrowing** (reported, not an error).
   - precondition rejects, Python raises: dropped.
   Report the share kept. If under 30 % of the generated inputs are kept, shape the generator
   (not the filter) so that more fall inside, and keep a part of the budget on unshaped inputs.
5. **Size**: at least 2,000 kept cases per unit, unless the Lean is too slow: then say what was reached
   and the time of one call. Keep an eval input under about 6,000 characters; split the seeds over
   several calls.
6. **Calls first-hand, outputs by script.** Run every `eval_decl` yourself with the input text
   exactly as in `work/<suite>.inputs.json`. Do not type the outputs: run
   `python3 diffeval/fuzz_collect.py <your number> <suite>`: it takes each output from the tool
   results of your own session record, matching the echoed input to the generated input character
   for character (an input you mistyped is reported as not run), and writes `work/<suite>.out.txt`.
   Then `compare.py` as usual.
7. **Files**: generator `diffeval/units/fz_<unit or task>_gen.py`, suite name `fz_<...>`; the
   generator also writes `work/<suite>.fuzz.json` (format in `diffeval/fuzz_receipt.py`), and every
   case carries `"fz": "kept"` or `"rejected"` (and `"covers"` when a case digests several inputs).
   Receipt: `python3 diffeval/fuzz_receipt.py <suite>` adds your rows to
   `diffeval/receipts/fuzz_2026-11-16.tsv`.

## A difference

Reduce it to the smallest input that still differs (fewest rows, simplest values), keep the seed.
Decide by a first-hand run which side the fault is on if you can (the Lean, the generator or its
Python rendering, the precondition, a recorded limit of the preludes in RULEBOOK section 6).
Send it to the unit's owner AND to port-translator-1, who passes it to the lead: unit, seed, minimal
input, Python value, Lean value, your reading. **Nothing is re-submitted** before the lead says so:
a re-submission clears the compositions.
